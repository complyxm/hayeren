# russian.md — ロシア語レイヤー

## 0. 前提（確定）

| 項目 | 決定 |
|---|---|
| キリル文字 | **学習者は読める。文字モジュールを作らない** |
| 目的 | **エレバンでの実用**。アルメニア語理解の補助ではなく独立したレイヤー |
| 語彙 | 弱い → フレーズ単位のチャンクで入れる |
| ロシア語の文法コース | **作らない。** フレーム置換に必要な最小限のみ |
| 位置づけ | アルメニア語の**フォールバック**。第一言語はあくまでアルメニア語 |

---

## 1. スコープ（厳格に守る。膨らませない）

- **200〜300 フレーズ**。これを超えたら止まって相談する
- **場面に紐づかないロシア語を入れない。** 汎用単語帳を作らない
- ロシア語の格変化・動詞活用の体系的学習は**やらない**
- 目標は「流暢」ではなく「通じる」。ここを取り違えると第二のアプリになる

---

## 2. エレバンでロシア語が効く場面・効かない場面

**効く**
- タクシー、マルシュルートカの運転手（特に年配）
- 市場での値段のやり取り
- 50代以上の世代（ソ連期の教育でロシア語を習っている）
- ロシア語話者の移住者が働くカフェ・サービス業（2022年以降に増加）
- ソ連期の建物の表示、古い商品ラベル

**効きにくい**
- 若年層。英語のほうが通じることが多い
- 新しい看板や公的表示。アルメニア語と英語が主流

**実用上の原則：まずアルメニア語で試す。** 通じなければロシア語、それでもだめなら英語。
アルメニア語から入るほうが相手の反応が良い場面が多い。この順序をアプリ内でも明示する。

---

## 3. 干渉 ── このレイヤー最大のリスク

同じ場面を2言語で同時に学ぶと**想起干渉**が起きる。パン屋で口を開いた瞬間、
どちらの言語が出るか自分でも分からなくなる。放置すると両方が中途半端に壊れる。

### 対策（すべて必須）

1. **同一セッションで両言語を出題しない。** レビューキューを完全に分ける
2. **場面ごとにアルメニア語を先に固める。**
   該当場面のアルメニア語カードが SRS で安定してから、初めてロシア語を解放する
3. **画面上で2言語を並べない。** 配色とタイポグラフィで言語を明確に区別し、
   切り替え式にする

### 「併記」を採用しない理由

同じ画面に2言語を並べるのは、干渉を起こす条件として最悪の組み合わせ
（同一場面・同一タイミング・同一文脈）。読んでいるときは両方分かった気になり、
口に出すときに混ざる。**タブまたはトグルで切り替える。**

例外：`ru_cognate`（§5-1）だけは併記してよい。これは干渉ではなく
「同じ語である」ことを示すのが目的なので、並べる意味がある。

---

## 4. ロシア語の知識がアルメニア語に効くところ・害になるところ

### 効く

- **借用語。** `մարշրուտկա` ← маршрутка。ソ連期の日用・技術語彙に多い。
  片方を覚えるともう片方が半分ただで手に入る。**積極的にタグ付けして見せる**
- **格の概念。** ロシア語 6 格、アルメニア語 7 格。語尾はまったく違うが
  「名詞が役割によって形を変える」という発想自体は転移する

### 害になる（明示的に警告する）

- **文法性。** ロシア語には男性・女性・中性があるが、**アルメニア語には性がない**。
  ロシア語を知っているとアルメニア語に性を探してしまう。
  文法 L02 で「性は存在しない」と積極的に打ち消す
- **格の対応表を作らない。** 名前が似ていても用法が違う。
  一対一で対応させると誤用の温床になる

## 5. データ構造

### 5-1. 借用語タグ（Phase 4 の語彙スキーマに**今すぐ**足す）

```jsonc
{
  "hy": "մարշրուտկա",
  "ja": ["乗合バス"],
  "ru_cognate": { "form": "маршрутка", "note": "ロシア語からの借用" }
}
```

- optional フィールド。UI では「ロシア語由来」バッジを出す
- **Phase 4 の時点でフィールドだけ用意する。** 2,000 語作った後の追加は高くつく
- 中身を埋めるのは Phase 7 でよい

### 5-2. 場面フレーズ集（Phase 7）

**ロシア語はアルメニア語の「訳」ではない。同じ場面の別の言い方。**
だから語彙エントリに `ru` を足すのではなく、場面ごとに別ファイルを持つ。

```
content/
  scenarios/bakery.json   # アルメニア語
  ru/bakery.json          # 同じ場面のロシア語（別ファイル）
```

```jsonc
{
  "scene": "bakery",
  "lang": "ru",
  "requires": { "scenario": "bakery", "armenian_stable": true },
  "phrases": [
    {
      "ru": "Сколько это стоит?",
      "ja": "これはいくらですか",
      "source": "...",
      "status": "unverified"
    }
  ]
}
```

`requires.armenian_stable` が満たされるまで**解放しない**。
判定条件は `docs/curriculum.md` §5 の「安定」の定義に従い、
**その場面に紐づくアルメニア語カードの 80% 以上が「安定」**であること。

---

## 6. 出題形式

- キリル文字は読めるので**なぞり書きは不要**
- 語彙が弱いので、**タイピング想起**と**チャンク音読**を主軸に
- 4択は使わない（`docs/interaction.md` の原則はロシア語にも適用）
- 発音チェックはアルメニア語ほど作り込まない。目標は「通じる」レベル。
  録音と聞き比べの仕組みは Phase 3 のものを流用する

---

## 7. 検証

`CLAUDE.md` §7 の規則をそのまま適用する。**ロシア語も推測で埋めない。**

- ロシア語話者または信頼できる辞書で確認が取れていないフレーズは
  `status: "unverified"` のままにし、出題しない
- 特に**丁寧さのレベル**（ты / вы、命令形の角の立ち方）を間違えると
  実地で失礼になる。ここは必ず裏取りする

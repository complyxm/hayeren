# interaction.md — インタラクション設計

**このファイルの目的：4択とフラッシュカードだけのアプリにしないこと。**

---

## 1. 大原則：認識 < 想起 < 産出

学習効果も面白さも、この順に上がる。

| 段階 | 例 | 難度 | 転移 |
|---|---|---|---|
| **認識**（選ぶ） | 4択で正しい訳を選ぶ | 低 | 低 |
| **想起**（思い出す） | 訳を見て単語をタイプする | 中 | 中 |
| **産出**（作る・出す） | 手で書く／声に出す／文を組む | 高 | 高 |

**4択は既定の出題形式にしない。** 4択は「選択肢を消去法で潰す」ゲームになりやすく、
実際にエレバンで必要になる能力（読む・書く・言う）とは別の技能を鍛えてしまう。

### 4択を使ってよい唯一の場面
**「選ぶこと自体が目標技能である」とき。** つまり**知覚の訓練**：

- `պ` と `փ` を聞き分ける（2択）
- `ղ` と `գ` を聞き分ける
- 似た字形 `ղ / դ` を見分ける

これは正当。産出できない音は、まず聞き分けられないことが原因なので、
**知覚訓練は産出訓練の前提**として必要。ただしこの場合も
**反応時間を記録**し、「正解できる」ではなく「速く正解できる」を目標にする。

## 3. 主要インタラクションの詳細

### 3-1. なぞり書き（識別4択の置き換え）

「この文字はどれ？」の4択をやめ、**指で書かせる**。

- SVG の筆順パス上を指でなぞる。パスからの距離が閾値内なら進む
- 筆順が違えば止まる（形が合っていても順序が違えば不正解にする）
- **アルメニア文字は日本語話者にとって未知の運動なので、書くこと自体が記憶を作る**
- 手書き「認識」（自由に書いた文字を判定）は難しいが、
  **「なぞり」の判定はパスとの距離を測るだけなので簡単**。まずこちらで作る

### 3-2. 聞き分けチャレンジ

音声を再生 → `պ` か `փ` か2択でタップ。

- **反応時間を記録する。** 正解率が頭打ちになった後も、速度で伸びが見える
- 連続正解でテンポが上がり、間違えると戻る。演出ではなく難度調整として機能させる
- ここで鍛えた知覚が Phase 3 の VOT 産出訓練の土台になる。**必ず知覚 → 産出の順で配置**

### 3-3. 地下鉄ナビ・看板読み

**「読めた」という手応えは、抽象的なクイズからは出てこない。実物から出る。**

- 地下鉄：路線図を表示し、駅名をアルメニア語で読ませて経路を答えさせる。
  エレバンの地下鉄は駅数が少ないので**全駅制覇が現実的な目標になる**
- 看板：`ՀԱՑ`（パン）、`ԴԵՂԱՏՈՒՆ`（薬局）などの実写。大文字表記の練習を兼ねる
- 出題ではなく「読めるものが増えていく地図」として見せる

### 3-4. 文タイル（並べ替えの正しいやり方）

単なる語順パズルにしない。**アルメニア語特有の「助動詞が動く」現象を体で覚えさせる。**

```
Ես կարդում եմ։        （私は読む）
    ↓ 否定にする
Ես չեմ կարդում։       （私は読まない）
```

助動詞 `եմ` が分詞の**後ろから前へ飛ぶ**。タイルを動かして初めて腑に落ちる種類の規則で、
解説文を読むだけでは絶対に定着しない。**同種の変形を連続で出す**（肯定↔否定、平叙↔疑問）。

### 3-5. 活用マシン（出題しない画面）

格・数・定/不定のダイヤルを回すと、名詞の形が**即座に**変わる画面。正誤判定なし。

- 学習者が自分で規則を見つける。`գիրք → գրքեր` の母音脱落なども触って気づく
- **正解を当てさせる画面ばかりだと疲れる。** 触って遊べる画面を必ず1つ置く

### 3-6. 分岐ダイアログ（AIを使わない会話）

パン屋、マルシュルートカ、薬局などの場面を**手書きの分岐ツリー**で作る。

```jsonc
{
  "scene": "bakery",
  "node": "n01",
  "npc": { "hy": "Բարև ձեզ։ Ի՞նչ եք ուզում։", "ja": "こんにちは。何がご入用ですか" },
  "choices": [
    { "hy": "Երկու լավաշ, խնդրում եմ։", "next": "n02", "outcome": "ok" },
    { "hy": "Երկու հաց, խնդրում եմ։",   "next": "n03", "outcome": "different_item" },
    { "hy": "Ի՞նչ արժե։",                "next": "n04", "outcome": "asked_price_first" }
  ]
}
```

- **会話AIは使わない**（サーバー不要・コスト0の制約、かつアルメニア語のモデル品質が低い）
- 手書きツリーは**むしろ良い**。「量詞を間違えて8個買ってしまう」ような
  記憶に残る失敗を意図的に設計できる。AIの当たり障りない応答より学習効果が高い
- 選択肢はアルメニア語で提示する。日本語訳はタップで表示

## 4. 「面白さ」の正体について

**演出（ポイント・バッジ・紙吹雪）で作った面白さは慣れる。**
2週間で効かなくなり、その後は作業感だけが残る。

代わりに次の3つで作る。

1. **フィードバックの即時性と粒度**
   VOT チューナーが面白いのは、声を出した瞬間に点が動くから。
   「正解/不正解」は情報量が1ビットしかない。**数値・位置・軌跡で返す**
2. **できなかったことができる瞬間**
   昨日読めなかった看板が読める。これは慣れない
3. **失敗が面白いこと**
   分岐ダイアログで量を間違えてパンを8個買う。減点ではなく笑いにする

`CLAUDE.md` の非目標に「装飾的ゲーミフィケーション」が入っているのはこのため。
**連続日数の表示だけは例外的に許可**（習慣化に実効性がある）。ただし
途切れたときに責めない。「3日空きました。復習から始めます」とだけ言う。

## 5. 実装上の注意

- **1つのインタラクションを完成させてから次に行く。** 半端なものを10種類作らない
- すべてキーボードだけで操作できること。なぞり書きは代替手段（筆順の番号選択）を用意
- 判定の閾値（なぞりの許容誤差、反応時間の目標値）は
  **決め打ちにせず設定で調整できるようにし、実際に触って詰める**
- インタラクションの結果はすべて SRS カードの成績として記録する。
  「遊んだけど進捗に反映されない」画面を作らない
